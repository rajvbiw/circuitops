🔌 CircuitOps — Complete Run Guide
EKS + Terraform + Kubernetes + Prometheus + Grafana
Total Time: ~20-30 minutes | Cost: ~$0.10/hr (t3.medium × 2 nodes)

📁 Final Terraform File Structure

terraform/
├── providers.tf      ✅ AWS + Kubernetes + Helm providers
├── variables.tf      ✅ All variables
├── terraform.tfvars  ✅ Aapki actual values (gitignore mein hai)
├── vpc.tf            ✅ VPC, Subnets, IGW, NAT Gateway
├── eks.tf            ✅ EKS Cluster + Node Group + IAM + OIDC
├── monitoring.tf     ✅ Prometheus + Grafana + NGINX Ingress (Helm)
├── main.tf           ✅ App resources (Namespace, ConfigMap, Deployments...)
└── outputs.tf        ✅ Cluster endpoint, kubectl command, access URLs

📈 PHASE 7 — Grafana Dashboard Queries (PromQL)
Grafana mein: Dashboards → New → New Dashboard → Add visualization

🔵 Dashboard 1: CircuitOps App Health
Panel 1 — Running Pods

promql

count(kube_pod_status_phase{namespace="gada", phase="Running"})
Visualization: Stat | Title: Running Pods

Panel 2 — Pod CPU Usage (%)

promql

sum by (pod) (
  rate(container_cpu_usage_seconds_total{namespace="gada", container!=""}[5m])
) * 100
Visualization: Time series | Unit: Percent

Panel 3 — Pod Memory Usage (MB)

promql

sum by (pod) (
  container_memory_working_set_bytes{namespace="gada", container!=""}
) / 1024 / 1024
Visualization: Time series | Unit: MiB

Panel 4 — Pod Restart Count

promql

sum by (pod) (
  increase(kube_pod_container_status_restarts_total{namespace="gada"}[1h])
)
Visualization: Table | Alert if > 3

🟠 Dashboard 2: Backend API Metrics
Panel 5 — HTTP Request Rate

promql

sum(rate(http_requests_total{namespace="gada"}[5m])) by (method, status)
Visualization: Time series | Unit: req/s

Panel 6 — Error Rate (5xx)

promql

sum(rate(http_requests_total{namespace="gada", status=~"5.."}[5m]))
/
sum(rate(http_requests_total{namespace="gada"}[5m])) * 100
Visualization: Gauge | Unit: Percent | Thresholds: 0=green, 1=yellow, 5=red

Panel 7 — P95 Response Time

promql

histogram_quantile(0.95,
  sum(rate(http_request_duration_seconds_bucket{namespace="gada"}[5m])) by (le)
)
Visualization: Time series | Unit: Seconds

🟢 Dashboard 3: Kubernetes Cluster Health
Panel 8 — Node CPU (%)

promql

100 - (
  avg by (node) (
    rate(node_cpu_seconds_total{mode="idle"}[5m])
  ) * 100
)
Visualization: Time series | Unit: Percent

Panel 9 — Node Memory (%)

promql

(
  node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes
) / node_memory_MemTotal_bytes * 100
Visualization: Gauge | Unit: Percent

Panel 10 — HPA Backend Scaling

promql

# Current replicas (line 1)
kube_horizontalpodautoscaler_status_current_replicas{
  namespace="gada",
  horizontalpodautoscaler="gada-backend-hpa"
}
# Desired replicas (line 2 — same panel mein add karo)
kube_horizontalpodautoscaler_status_desired_replicas{
  namespace="gada",
  horizontalpodautoscaler="gada-backend-hpa"
}
# Max replicas (line 3)
kube_horizontalpodautoscaler_spec_max_replicas{
  namespace="gada",
  horizontalpodautoscaler="gada-backend-hpa"
}
Visualization: Time series

🔴 Dashboard 4: Alerts Setup
Grafana → Alerting → Alert Rules → New Alert Rule

Alert 1: Pod Down

promql

count(kube_pod_status_phase{namespace="gada", phase="Running"}) < 3
Fire when: IS BELOW 3 | For: 2m | Severity: Critical

Alert 2: High CPU

promql

avg(rate(container_cpu_usage_seconds_total{namespace="gada"}[5m])) * 100 > 80
Fire when: IS ABOVE 80 | For: 5m | Severity: Warning

Alert 3: Pod Crash Loop

promql

increase(kube_pod_container_status_restarts_total{namespace="gada"}[15m]) > 2
Fire when: IS ABOVE 2 | For: 0m | Severity: Critical

🆘 Troubleshooting
Problem	Fix
Error: no valid credential sources	aws configure dobara run karo
Error: cluster not ready	4.2 step mein 2-phase apply use karo
ImagePullBackOff	ECR image URL main.tf mein update karo
Grafana mein No data	Prometheus targets check karo: http://localhost:9090/targets
Pods Pending state mein	kubectl describe pod <name> -n gada se reason dekho
NAT Gateway error	EIP limit check karo (default 5/region)
📋 Quick Cheatsheet
bash

# === AWS ===
aws sts get-caller-identity                    # Identity check
aws eks update-kubeconfig --region ap-south-1 --name circuitops-eks
# === TERRAFORM ===
terraform init                                 # Initialize
terraform plan                                 # Dry run
terraform apply -target=aws_eks_cluster.circuitops  # Phase 1
terraform apply                                # Phase 2 (full)
terraform destroy                              # Delete all
# === KUBECTL ===
kubectl get nodes                              # Nodes status
kubectl get pods -n gada -w                    # App pods watch
kubectl get pods -n monitoring                 # Monitoring pods
kubectl logs -f <pod-name> -n gada             # Pod logs
kubectl describe pod <pod-name> -n gada        # Pod details
# === PORT FORWARD ===
kubectl port-forward svc/prometheus-stack-grafana 3000:80 -n monitoring
kubectl port-forward svc/prometheus-stack-kube-prom-prometheus 9090:9090 -n monitoring
